# pii-airlock-extension — Agent Context

## What this project is

A **standalone WXT browser extension** (Chrome/Edge MV3 + Firefox MV2) that automatically detects and obfuscates PII in any AI chat interface before the user sends a message.

- **No backend required.** Zero install friction — installs from browser store, works immediately.
- **Pure JS detection engine** bundled inside the extension (compromise.js NER + regex).
- Targets (verified live): ChatGPT, Claude, Gemini, Copilot, Perplexity, Mistral. Other adapters (Poe, character, huggingface, you) exist but are not shipped until verified on the live site.
- Enhanced mode via the `pii-airlock` proxy (localhost:8745) is NOT implemented (no code talks to it). Do not document it to users until it exists; "better detection" today = the opt-in on-device names model.

## Related project

`../pii-airlock/` — Python CLI + proxy. Reference for token format and logic only; the extension does not call it today.
See `../pii-airlock/pii_scrub/` for the reference detection/mapping/payload logic.
Token format `<ENTITY_TYPE_N>` is shared between both projects.

## Tech stack

- **WXT** `0.20.26` — cross-browser extension framework (Vite-powered)
- **React 19** — popup + options UI
- **Bun** — package manager and test runner (`bun test`)
- **TypeScript** strict mode
- **compromise** — lightweight English NLP for person/place/org detection
- **franc-min** — language detection, routes to language-specific regex variants

## Detection layers

### Layer 1 — Regex (synchronous, ~0ms)
Covers structured PII: EMAIL_ADDRESS, PHONE_NUMBER, CREDIT_CARD (+ Luhn),
IBAN_CODE, SSN, IP_ADDRESS, CRYPTO, SECRET_KEY (Bearer/sk-/ghp_ prefixes).

### Layer 2 — NLP via compromise.js (~10–20ms)
Covers unstructured PII: PERSON, LOCATION, ORG.
Lexicon + capitalisation based — misses novel surnames and non-English given
names ("Jean", "Élodie"). Instant fallback when Layer 3 is unavailable.

### Layer 3 — Transformer NER via @huggingface/transformers (~150–300ms)
ONNX/WASM `Xenova/bert-base-multilingual-cased-ner-hrl`. Multilingual; reads
grammatical context (not a name list) so it catches novel surnames + non-English
names. Scores PERSON ~0.9 > compromise 0.75 → wins the overlap dedupe.

- **Where it runs:** NOT the content script (would bloat content.js ~60MB +
  block the page). Chrome/Edge MV3 → **offscreen document** (`entrypoints/offscreen/`).
  Firefox MV2 → persistent **background** page. Routing seam: `lib/detection/ner-client.ts`
  (swappable transport, no static `./ner` import) → content wires a
  `browser.runtime.sendMessage` transport → `background.ts` dispatches to
  offscreen (`NER_DETECT` → `NER_DETECT_OFFSCREEN`, two types so the broadcast
  doesn't loop).
- **Network (invariant #3, reworded):** your TEXT never leaves the device. The
  model is never packaged: the user opts in (Options → "Better name detection"),
  which downloads it ONCE from a pinned HF revision (`lib/ner-manifest.ts`),
  SHA-256 verified, into the Cache API (`lib/ner-model.ts`). Inside the pipeline
  `configureNerEnv()` serves files only from that store (`env.customCache`) and
  `env.fetch` rejects, so a miss fails open instead of reaching out. The packaged
  ORT runtime (`public/wasm/ort-wasm-simd-threaded.{mjs,wasm}`, ~14 MB raw /
  3.7 MB gzipped) is pinned through `wasmPaths`; the build fails if it is
  missing (`build:before` hook) and a Vite plugin drops ORT's own 27 MB copy.
- **Fail-open:** load/inference errors → `[]`; L1+L2 still run. NER no-ops until
  `configureNerEnv` is called AND the model is installed. Sends wait at most
  `NER_BUDGET_MS` (400 ms) for it; `DetectionResult.nerTimedOut` records a skip.
  The model is warmed on composer focus, not page load.
- **Model output shape:** transformers.js returns per-wordpiece BIO tokens with
  NO offsets. `mergeTokens` aligns them to the text with a cursor and bridges
  O-tagged hyphens; `chunkText` windows long text. Tests replay captured real
  output (`tests/fixtures/ner-real.ts`), not hand-made shapes.
- **One host for both browsers:** `offscreen.html` hosts the model. Chrome uses
  `chrome.offscreen`; Firefox MV2's background page embeds it in a hidden iframe.
  Transformers therefore never lands in `background.js`.
- **Expected build warning (Firefox only):** `[EMPTY_IMPORT_META] import.meta …
  iife`. transformers' `import.meta.url` self-location is neutered in the MV2
  iife background — harmless because `configureNerEnv` overrides both
  `localModelPath` and `wasmPaths`, so that resolution path is never used.
- **Tests:** `lib/detection/ner.ts` exposes `__setNerRunner()` to inject a fake
  runner — unit tests never load the real model (`tests/detection/ner.test.ts`).

## Policy

Modes: **auto** (default: structured data, secrets, names and DOB are replaced
silently; places, orgs and private IPs are only noticed), **review** (the same
set is shown in a panel before sending), **off**. Per-entity overrides win over
the mode; per-site off (`sitesOff` in sync) and a timed pause (`pausedUntil` in
local) are honoured by `isActive()`. UI: ONE status tab attached to the top
border of the composer pill (just after the left corner curve; flips under the
bottom border near the viewport top). States: "Protected" (shrinks to the icon
4 s after load / composer focus / route change), "N will be replaced" / "N to
review" (live scan, regex+compromise; click opens the panel), "Noticed",
"Checking…" (send-time analyze >150 ms), "Not protected" (paused). Driven by
`shield.setProtection` (content.ts health check), `shield.render` (scan) and
`shield.setChecking` (intercept). The pill is found by `lib/ui/frame.ts`
(`findFrame`: first decorated, rounded ancestor holding a button outside the
composer, <90% viewport wide; fallback LCA with send button → form → composer);
`ChatAdapter.findFrame?` overrides it where a live check fails. Panel and toast
hang off the tab. The modal exists only for real failures. The toolbar icon
only changes for warn (no composer found), the one state with no field to mark. Legacy `strict`/`permissive` values map to `auto`.

**UI theme:** never hard-code colours. `theme.ts` samples the page and sets
`--bg --fg --accent --accent-fg --font --radius` on the shadow host; derived
tones use `color-mix`. Keep copy short, no emoji, no gradients.

## Token format

`<ENTITY_TYPE_N>` — e.g. `<EMAIL_ADDRESS_1>`, `<PERSON_2>`.
Identical to pii-airlock Python format. BrowserMapping holds token↔value in
the content script's memory, mirrored per tab in `storage.session` (RAM only,
dropped when the browser closes, removed when the tab closes) through the
background (`MAP_LOAD`/`MAP_SAVE`), so a reload keeps numbering. Never in
storage.local/sync. Panic clear wipes it.

**Restore (`lib/restore.ts`):** a MutationObserver edits text-node `nodeValue`
in place (no wrappers, composers/textareas skipped), so the page shows real values
while the backend only ever got tokens. Selector-free by design. Known limits:
native Copy buttons copy tokens; a markdown renderer that swallows `<TOKEN_1>` as
an unknown HTML tag leaves nothing to restore (needs a live-site check per site);
old chats opened after a browser restart show tokens.

## Key invariants (never break these)

1. **Fail-closed**: if detection throws, the send is BLOCKED (Edit or explicit "Send unchecked"), never silently allowed.
2. **No page text in persistent storage**: BrowserMapping lives in memory (plus the RAM-only `storage.session` copy). `storage.sync` holds settings only. `storage.local` holds the counter, pause and the user's own allow/deny values (typed or chosen by them; never synced). Panic clear wipes lists + mapping.
3. **No network calls**: extension never sends text to any remote service (the only fetch is the opt-in, checksum-verified names-model download).
4. **Adapters are fragile**: provider UI changes break selectors. MutationObserver re-attaches on DOM changes. Adapter version strings must be bumped on selector updates.

## Adding a new AI chat site

1. Create `lib/adapters/<sitename>.ts` implementing `ChatAdapter`.
2. Add `host_permissions` entry in `wxt.config.ts` manifest.
3. Add `matches` entry in content script definition.
4. Register adapter in `lib/adapters/index.ts`.
5. Add frozen HTML snapshot + tests in `tests/adapters/<sitename>.test.ts`.

## Open questions / decisions already made

| Question | Decision |
|---|---|
| UI framework | React 19 (already installed) |
| Test runner | bun test. DOM-level tests (`tests/adapters/`) use `happy-dom` via `@happy-dom/global-registrator`. |
| DOM emulator caveat | happy-dom AND jsdom both mis-model **at-target listener order** (they fire capture-before-bubble on the target; real browsers fire in *registration order*). This is the exact quirk behind the claude.ai keydown leak, so it CANNOT be regression-tested in an emulator — that test would pass on the broken code. Such tests belong in a real-browser harness (Playwright). happy-dom also has no `execCommand`, so `replaceContentEditable`'s native path is untestable there. |
| Options storage | sync: mode, overrides, sitesOff. local: counter, pausedUntil, lists |
| Restore tokens in AI response | On: page text nodes show real values (display only) |
| Detection language | navigator.language → fallback en |
